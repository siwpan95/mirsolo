# 数据口径 —— 逐表来源、近似标记与已知差异

> 最后更新：2026-10-19 ｜ 口径：**国服 1.76 复古版骨架 + 韩 2 特色子系统**（D3 = C）
>
> 原则：**每个数字都要能追到来源**；凡属近似，必须显式标 `CALIBRATE`，
> 并在 P1 用实测战斗日志回归校准。绝不把"看着像"当成"就是"。

## 通用约定

| 项 | 约定 |
|---|---|
| 属性写法 | `(下限, 上限)`，对应原版"攻击 0-30"这类区间写法 |
| 六维缩写 | `dc` 攻击 / `mc` 魔法 / `sc` 道术 / `ac` 防御 / `mac` 魔御 |
| 万分比 | 概率与权重统一用 `permille`（10000 = 100%），避免浮点漂移 |
| 等级需求 | 以"穿戴/学习所需等级"为准，不是掉落等级 |
| 单位 | 经验为整数点；时间秒；重量/持久沿用原版整数口径 |

## exp（`data/exp.json`）

- **语义**：`levels["N"]` = 从 N 级升到 N+1 级所需的**本级经验**（不是累计）。`"50": 0` 表示封顶。
- **来源**：公开整理的 1.76 经验表（多来源交叉：VMOS 云手机攻略 / 无度站 / 嘟嘟传奇等），逐值手录。
- **已知差异（重要）**：网上流传"1→50 总经验 10.8185 亿"，但**按该表逐级相加实际为
  `1,044,796,900`（约 10.45 亿）**，差 3,705 万。二者不可能同时成立——网页的"总计"
  与其自身逐级数值不自洽。本项目以**逐级数值**为准（因为升级判定逐级进行），
  `tests/test_exp.py::test_exp_total_matches_table` 钉死 1,044,796,900。
- **影响**：若 P1 拿到更权威的表（如客户端 `ExpList.ini` 的公开整理版），
  只需替换 JSON 并同步该断言，代码零改动。

## classes（`data/classes.json`）

- **语义**：成长字段 `*_per_levels = N` 表示**每升 N 级 +1**，步长固定 1。
  例：`dc_min_per_levels = 4` 即"每 4 级攻下限 +1"。
- **近似标记**：`CALIBRATE`。原版逐级成长表未公开，本表为平滑近似：
  - 1 级战士：HP 20 / DC 1-2 / AC 0-2 / 准确 5 / 敏捷 5 / 负重 30
  - 5 级：HP 36 / DC 2-4 / AC 0-3 / 准确 7 / 负重 38
  - 35 级（裸装）：HP 156 / DC 9-19 / AC 6-13
- **为什么用整数除法**：与确定性随机流同源，跨平台逐位一致；同时避免
  "1 级多加 0.4 点攻击"这种在原版里不存在的半值。
- **P1 校准方法**：用官方/开源服务端公开的 `BaseStats*.ini` 结构做对照
  （只看字段语义与量级，不搬运数据文件），再用实测战斗日志拟合。

## skills（`data/skills.json`）

- **P1-S1 范围**：16 技三职业全覆盖——战士 4（攻杀 7 / 刺杀 19 / 半月 22 / 烈火 32）、
  法师 5（火球 7 / 雷电 17 / 火墙 24 / 魔法盾 31 / 冰咆哮 35）、
  道士 7（治愈 7 / 施毒 14 / 火符 18 / 召骷髅 19 / 隐身 21 / 群疗 26 / 召神兽 35）。
  学习等级按公开资料。
- **`power_permille`**：`CALIBRATE`。原版技能伤害系数未公开，
  这里取"相对强度"近似（烈火 1800 最高、火墙 800 最低）。
- **`kind` 与实现分区**：P1-S2 起 11 种 kind **全部有行为**——
  伤害/治疗（physical / physical_aoe / magic / magic_aoe / taoist / heal / group_heal）
  与状态/召唤（poison / buff_shield / buff_invis / summon）。
  `PLANNED_KINDS` 现在必须为空：**表里新增 kind 而引擎没实现，测试立刻红**
  （`test_no_kind_lags_behind_implementation`）。
  kind 全集唯一定义在 `mirsolo/data/loader.py::SKILL_KINDS`，引擎从那里导入。
- **技能书**：每技一本（`book` 字段 ↔ items.json 里 `kind: "book"` + `teaches` 双向校验）。
  学会即消耗一本；已学再学幂等不吃书。价格 = 500 × 学习等级（`CALIBRATE` 近似）。
- **熟练度**：每成功施放 +1，封顶 3（`MAX_PROFICIENCY`）；被拒的施放不涨。
  P2 再把熟练度接进伤害/命中加成。
- **三道门**：学习（职业 + `level_req`）→ 资源（`cost_mp` + `cooldown`，
  miss 也扣费，与原版"空放就是空放"一致）→ 距离（切比雪夫 ≤ `range`）。
  **被拒的意图直接丢弃并发 `skill:rejected`**——若留在队列里重试，
  冷却一过"几秒前按歪的技能"会自动生效（实测踩过）。
- **AoE 语义**：以**目标**为中心、切比雪夫 `aoe_radius` 内逐个独立结算
  （每个受害者自己的随机流，非伤害均摊）。

## classes 的 mc/sc 成长（P1-S1 补齐）

- P0 时 `grow_attributes` 把 mc/sc 硬编码为 (0,0)，法师/道士放不出有意义的技能。
- 现按职业表显式成长：法师 `mc_base [0,1]`、每 3 级 +1 下限 / 每 2 级 +1 上限；
  道士 `sc_base [0,1]`、每 4 级 +1 / 每 3 级 +1；战士 mc/sc 恒 0（显式写 0 不省略）。
- **`CALIBRATE`**：17 级法师 mc ≈ (5,9)，雷电 ×1.35 → 单发 ~7-12，
  与"法师中期主力"的定位量级相符；P1 用实测练级节奏回归。

## monsters（`data/monsters.json`）

- **对齐公开口径**：鸡 10 经验 / 鹿 20 / 僵尸 150 / 尸王 300。
- **`CALIBRATE`**：`dc` / `ac` / `hp` / `accuracy` / `agility` 为近似；
  稻草人 12 经验、骷髅 90 经验为估算（未找到一致来源）。
- **`ai` 语义**：`passive`（被打才还手）/ `flee`（低血逃跑）/ `aggressive`（主动）/ `elite`（BOSS 模板，P1 起分层）。

## items（`data/items.json`）

- **`kind` 大类**：`equip`（装备，`slot` 必填）与 `book`（技能书，
  `teaches` 指向技能 id、`slot` 必须为 null）；loader 双向校验
  技能 ↔ 技能书（书指向的技能必须存在，技能挂的书也必须存在）。
- **P0 八件装备**：木剑、乌木剑、斩马刀、布衣、青铜盔甲、中型盔甲、皮头盔、青铜头盔。
- **P1-S2 十六本技能书**：每技一本（`book_<skill_id>`，名如《火球术》）。
- **`CALIBRATE`**：`atk` / `ac` 区间为近似；等级需求与重量参考公开装备表。
- **贵重装备暂不入表**：裁决 0-30 / 屠龙 5-35 / 骨玉魔 2-6 / 圣战法神天尊套
  属 P1-P2 内容，待该批次再逐件录入并标来源（避免"先录一堆没校准的数"）。

## drops（`data/drops.json`）

- **语义**：每组独立 roll 组权重（`permille`，非互斥，可同时掉多组）；
  命中后组内按 `permille` 权重挑一条；`gold` 单独 roll 区间。
- **防刷设计**：结果由 `(world_seed, species, kill_index)` 决定，
  `kill_index` 来自世界状态并随存档持久化 → 读档重打同一只怪掉落不变。
- **`CALIBRATE`**：所有权重为初始近似，P1 按"每小时期望收益"校准到原版手感
  （原版典型：小怪 ~1/4~1/8 掉一件普通装备，BOSS 必掉 + 追加组）。

## maps（`data/maps.json`）

- **P1 八张**，等级带 1-50 连续：比奇省外围 1-10 → 比奇矿洞一层 11-20 →
  蜈蚣洞一层 20-26 → 半兽古墓一层 26-33 → 沃玛寺庙 33-40 → 石墓阵 40-44 →
  封魔谷 44-47 → 祖玛寺庙 47-50。连续性 + 传送**有向**可达由门禁
  `map-bands` 钉住（无向 BFS 会把对方出口当本图入口，孤岛图测不出来，踩过）。
- **P0 起点**：比奇省外围（野外 64×64）。
- **`CALIBRATE`**：尺寸与刷新数量按"单人练级节奏"设定（原版地图更大、密度更高，
  但单机没有必要让玩家跑空图）；刷新间隔 20-180 秒。
- **结构校验覆盖**：传送点坐标必须落在图内（调小尺寸后忘改坐标是高频事故，
  已被 `test_data.py::test_out_of_bounds_portal_is_caught` 钉住）。

## 战斗公式（`mirsolo/combat/formulas.py`）

| 项 | 公式 | 性质 |
|---|---|---|
| 命中率 | `clamp(7500 + (准确 − 敏捷) × 300, 2000, 9700)` 万分比 BP | `CALIBRATE`：线性近似，原版为分段表 |
| 物理伤害 | `max(1, roll(dc) × 倍率 − roll(ac))` | 结构对齐原版（先命中后 roll 攻防） |
| 魔法伤害 | `max(1, roll(mc) × 倍率 − roll(mac))`，**无视 AC** | 结构对齐 |
| 道术伤害 | `max(1, roll(sc) × 倍率 − roll(mac))` | 结构对齐 |
| 治疗 | `roll(sc) × 倍率`，不抵扣 | 结构对齐 |
| 出手间隔 | `1.50 − 0.10 × 攻速档位`（1.40 ~ 0.40s） | `CALIBRATE` |

**为什么"最小伤害 = 1"**：原版命中即至少 1 点，这是"高防也磨得死"的底层保证；
若改成 0，低攻角色会被高阶怪永久锁死，与单机（无组队救援）不相容。

### 两套"比率"尺度必须分清（曾经踩过）

| 用途 | 尺度 | 记号 | 100% 等于 |
|---|---|---|---|
| **概率**（命中、掉落组） | 万分比 | `*_BP` / `permille` 字段 | `10000` |
| **倍率**（技能加成） | 千分比 | `power_permille` | `1000` |

事故记录：`resolve_physical` 掷点用 `rand_int(1, 10000)`（万分制），
而命中常量曾按千分制写成 `750`（本意 75%），结果实际命中率只有 **7.5%**，
而"断言 chance 数值"的公式单测全绿——因为**掷点与阈值不同尺度**这件事
没有任何断言在管。现已被两类断言钉住：

1. `formulas.HIT_ROLL_DENOMINATOR` 与命中常量同处一节，注释互指；
2. `tests/test_formulas.py::test_hit_rate_matches_declared_chance`
   直接统计 4000 次真实结算的命中频率，期望值写**字面量** `7500/8400/6600`，
   容差 ±150 BP（注入千分制常量或千分制掷点都会立刻变红）。

**P1 校准计划**：录制 500 场同配置战斗，统计实际命中率与伤害分布，
反推 `HIT_BASE_BP` / `HIT_PER_POINT_BP` 与技能倍率；
校准前后各存一份 `docs/calibration/*.json` 作为证据。

## 换图与面板（`mirsolo/world/`、`mirsolo/presentation/panels.py`）

### 传送（踩上去就过）

- 判定是**同格**（切比雪夫距离 0），不是"附近"——站旁边一格就被传走，
  玩家只会觉得地图在抽风。
- 落点 = 目标图里 `to == 来源图` 的那个回程口**向地图内侧偏 3 格**。
  直接落在回程口上会被立刻判定成"又踩到了"，刚进图就被弹回；到达后另有
  2 刻免疫窗口（`portal_grace_until`）兜住极端地图数据。
- 换图**不重建玩家**（`spawn_player` 的 eid 固定，重建 = 清空血量背包等级），
  只搬位置；旧图实体全清，新图按刷新表重铺（与开局同一条路径
  `world.spawn.spawn_map_monsters`，随机流名固定，同图每次进出配置一致）。
- 换图做成 **`PortalSystem`（priority 95，最后跑）** 而不是"窗口每帧查一次"：
  窗口走 `engine.advance()`，headless 走 `session.step()`，两条入口；
  规则写进系统才不会分叉。

### eid 唯一性（静默覆盖，真实踩过）

`World.create_entity` 撞到已存在的 eid **既不报错也不加实体**（实测），
而 `entity_count()+1` 会因清尸体/换图**倒退**——新怪直接顶替活着的旧怪，
表现成"怪凭空少一只"。现在 eid 走 `factory.next_entity_id`：
world data 里只增不减的序号 + 存在性兜底，由
`test_travel.py::test_entity_ids_stay_unique_across_round_trips` 钉住。

### 面板（C 角色 / B 商店 / V 仓库）

- 布局是**纯几何**（`panels.py`），命中测试、行重叠、出屏都可单测；
  窗口层只负责"把行转成一次规则调用"，**不在窗口里重算价格或门槛**——
  两套判定必然分叉，分叉出来的 bug 只有玩家能碰到。
- 点一次 = 操作**一件**（买卖/存取都是 1，不是整叠）：误点一下卖掉
  20 件药是灾难。
- 商店是**随身商铺**（任意地图可开）——刻意简化：原版商店在城镇里，
  但单机没有"回城"动线，随身商铺的代价可接受；价格仍走 `shop.buy_price`
  单一口径，回收价 = 买入价 // 3，"买进卖出必亏"有用例锁死。
- 货架按 (价, id) 升序；一屏放不下时滚动（滚轮），上下端标"还有几种"——
  直接截断会让技能书永远买不到。
- 钱不够/等级不够的行**保留并显灰**（附原因），不整行消失：
  玩家需要看到自己差多少，而不是猜货架空了一块。
